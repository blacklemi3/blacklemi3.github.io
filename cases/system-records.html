硬件与设备

双 MCU 机器人控制链路

参与语音交互主控与运动控制板的联调：ESP32-S3 负责语音、联网、屏幕和指令调度，Hi3863 解析动作指令，再通过 PCA9685 控制舵机。重点是把用户输入转换成结构化动作，并通过 UART 帧协议连接执行端。

相关经历包括指令下发、动作反馈、协议联调和交接说明。原固件与设备文件本地保留，当前页面为历史经验说明。

外设驱动与试验箱案例

编写和适配 Python 外设驱动与部分 C 封装，涉及 I2C 温湿度读取、OLED 显示、PCA9685 电机和舵机控制，以及 GPIO、PWM、UART 等接口。将驱动与实验案例、烧录步骤、串口调试说明放在一起交付。

边缘视觉部署

参与 K210 / Maix / CanMV 风格设备的视觉项目验证，涉及标注、类别列表、模型元信息和设备启动脚本的衔接。公开版本提取出部署前检查流程，能够发现标注框越界、类别重复、文件引用不一致等问题。

视觉部署检查工具使用虚构标注和模型占位文件；本轮 7 项 Python 测试通过，不包含真实模型训练或设备推理测试。

ESP32-C3 BLE / UART 公开示例

一个示例接收 BLE 文本命令，解析后控制 LED、转发 UART 并通知状态；另一个示例扫描控制器广播，将预设输入包解析为摇杆、扳机和按键状态。

控制器解析示例使用固定样例包，不包含真实 Xbox 连接及连续输入订阅。仓库保留历史编译记录，本轮未重新编译或烧录。

“喝啥” ArkTS 轻应用

围绕“今天喝什么”的即时选择场景，设计 HarmonyOS NEXT / ArkTS 应用原型，组合抽卡反馈、历史记录与轻量成长规则。

按 MVVM 组织页面、组件、服务、数据模型和存储。规则层处理概率、保底、时间权重和历史权重，界面层负责状态转换与结果反馈。

这段经历主要对应产品规则、组件组织和状态管理。原型与历史资料本地保留，当前页面不声明已上架或有经过验证的用户规模。

网络变更与回滚

参与 VLAN、OpenWrt / iStoreOS 配置变更与运行说明整理。针对远程变更后失联的风险，流程包括配置备份、延迟回滚、连通性验证及验证通过后取消回滚。

这一经验延续到本地工具和数据任务里：在执行前定义能检查的结果，在失败时保留恢复路径，并把运行日志作为交接的一部分。

官网与内部工具交付

完成静态官网和内部知识工具的上线相关工作，涉及备案迁移、HTTPS、Nginx、搜索验证，以及登录、访问记录、水印和会话控制。
