本地开发工具链与项目交接工作台

把检查命令和运行结果
放回项目交接里。

这是一个可以在本地试用的小工作台：浏览样例项目，运行事先定义的检查，然后带着本次结果生成一份交接说明。

IN THIS PROJECT为什么做输入与输出三步运行本轮验证

接手目录时，先找得到入口

一个目录里可能同时有 Python 脚本、Node 应用和设备项目。交接常见的困难是：说明文档分散、检查方式不一致、运行日志没有和项目放在一起。

我把工作中连接界面、本地服务与子进程的经验，整理为独立的公开样例。使用者可以在一页看到项目摘要、预设检查及执行结果。

个人实现

Node.js 本地 HTTP 服务、静态前端、项目卡片、命令白名单、子进程日志收集与 Markdown 交接生成。

公开样例范围

3 个虚构项目：Python 资产工具、Node 检查面板、ESP32 项目说明。只处理仓库自带样例。

从项目目录到交接说明

  1. 输入：样例工作区读取 README、依赖与工程标记，展示项目摘要、技术类型和待检查的文件名线索。
  2. 处理：预设命令执行选择项目后，由服务端白名单决定命令。界面接收标准输出、错误输出与退出码，保留本次运行结果。
  3. 输出：Markdown 交接将项目说明、运行方式和检查结果合并，供下一位使用者查看入口及继续处理问题。

服务监听 127.0.0.1。项目名与路径经过校验，执行入口只接受服务端配置的样例命令。

三步运行

需要 Node.js 18+ 和能通过 python 命令启动的 Python。服务本身使用 Node.js 标准库。

1. 获取公开仓库

git clone https://github.com/blacklemi3/local-handover-workbench.git
cd local-handover-workbench

2. 启动本地界面

node server.js

在浏览器打开 http://127.0.0.1:5188，选择 python-asset-tool，运行检查并生成交接说明。

3. 运行样例检查

node scripts-smoke.js

预期输出：

local-handover-workbench smoke test passed
打开仓库 ↗只需要目录索引？看 CLI 工具 ↗

本轮验证了什么

2026-09-06，在当前电脑上用现有 Node.js 与 Python 运行仓库自带 smoke 检查，结果通过。

  • 读取样例项目列表，确认至少包含 3 个项目。
  • 通过服务接口执行 Python 样例测试，确认退出码为 0。
  • 生成 Markdown，并检查交接说明内容。
这是一条样例流程检查，不等于任意真实工作区都已验证。公开工具保留命令白名单；接入新项目时，需要显式定义可运行命令并复查生成内容。
